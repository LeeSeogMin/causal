# 1부. 예측 문제를 세우고 첫 예측을 얻는다

## □ 1부 개요

○ 이 파트가 끝나면: 학습 없는 기준선 세 개와 딥러닝 모델 세 개의 24시간 예측 오차를, 같은 테스트 구간·같은 지표로 나란히 놓고 읽을 수 있다

○ 다루는 절: 9.1 ~ 9.4

## □ 9.1.1 왜 시간 순서를 따로 다루는가

○ **시계열(time series)** 은 값이 시간 순서대로 적힌 자료다. 설문 자료에서는 응답자 1번과 500번의 행을 바꿔도 분석 결과가 달라지지 않지만, 전력 수요 자료에서 3월과 8월을 바꾸면 자료 자체가 무너진다

– 순서가 곧 정보이기 때문에, 표 자료에서 쓰던 절차(무작위로 섞어 나누기 등)를 그대로 가져오면 성능이 부풀려진다. 어디서 부풀려지는지는 9.2.2에서 확인한다

○ 시계열이 표 자료와 다른 지점은 세 가지다

– 첫째, 오늘 값이 어제 값과 붙어 있다. 전력 수요는 하루 전 같은 시각, 일주일 전 같은 시각과 특히 비슷하게 움직인다. 시계열이 제 과거와 닮는 이 성질을 **자기상관**이라고 부른다

– 둘째, 주기가 겹쳐 있다. 실습 데이터에는 1년 주기(여름·겨울 냉난방), 일주일 주기(주중·주말), 하루 주기(오후·저녁의 두 피크)가 함께 들어 있다

– 셋째, 관계가 도중에 바뀐다. 실습 데이터에서는 전체 기간의 50% 지점부터 정책 효과가 들어가 수요 수준이 서서히 이동한다

○ 자기상관은 이렇게 잰다: 시계열 전체를 k칸 밀어 놓고, 민 것과 원래 것이 얼마나 닮았는지 상관으로 계산한다. k=24면 하루 전 값과, k=168이면 일주일 전 값과 비교하는 셈이다

– 판정 눈금: 시차 24와 168에서 자기상관이 뚜렷하게 남아 있으면, 그 시차의 값을 입력 변수로 넣는다. 반대로 어느 시차에서도 자기상관이 거의 0이면 그 계열은 순서 정보가 없는 잡음에 가까우므로, 복잡한 모델 대신 평균값 예측으로 끝내는 편이 낫다

**한 줄 정리: 시계열에서는 순서가 정보다. 순서를 무시한 절차는 성적을 부풀린다.**

## □ 9.1.2 신경망이 학습하는 것 — 작은 분류 실습

○ 전력 수요와 기온의 관계는 직선이 아니다. 기온이 25도에서 30도로 오르면 냉방 수요가 급히 늘지만, 15도에서 20도로 오를 때는 거의 변하지 않는다. 직선 하나로는 이 굽은 관계를 담을 수 없다

○ **신경망**은 입력을 넣으면 출력이 나오는 계산 공식을 데이터에서 찾아내는 방법이다. 값을 곱하고 더하는 단위를 여러 층으로 겹쳐, 굽은 관계도 표현한다

– 학습은 두 단계의 반복이다. ① 현재 공식으로 예측을 만들고 정답과의 차이(오차)를 잰다. ② 공식 안의 숫자(가중치) 하나하나가 그 오차에 얼마나 기여했는지 거꾸로 계산해, 기여가 큰 숫자를 더 크게 고친다. 이 거꾸로 계산을 **역전파**라고 부른다

○ 본격적인 시계열에 들어가기 전에, 가장 단순한 신경망(MLP)으로 정책 성공/실패 분류를 한 번 돌려 본다. 데이터는 예산·집행률·대상 인구 등 6개 특성으로 정책 성공 여부를 맞추는 5,000건짜리 합성 자료다

○ 실습 코드(핵심 부분, 전체는 `9-mlp-example.py`)

```python
model = keras.Sequential(name='PolicyEffectMLP')
model.add(keras.layers.Input(shape=(input_dim,)))
for units in [64, 32]:                                   # 은닉층 두 개
    model.add(keras.layers.Dense(units, activation='relu'))
    model.add(keras.layers.BatchNormalization())
    model.add(keras.layers.Dropout(0.2))
model.add(keras.layers.Dense(1, activation='sigmoid'))   # 성공 확률 하나를 출력
```

○ 실행 결과(`results/9-mlp-example.log` 발췌)

```

  - 학습 완료 (총 23 에포크)

Test AUC-ROC: 0.6058

      Failed     precision 0.2308   recall 0.0160   (support 188)
     Success     precision 0.7490   recall 0.9822   (support 562)
```

– 해석: 정확도 74.00%는 높아 보이지만, 애초에 성공이 74.84%인 자료라서 "전부 성공"이라고만 답해도 74.84%가 나온다. 실제로 실패 188건 가운데 모델이 실패로 맞힌 것은 3건(재현율 0.0160)뿐이다. 이 모델은 다수 쪽으로만 답하는 규칙과 사실상 같은 성적이며, 채택할 수 없다

– 이 실패가 다음 절의 규칙으로 이어진다. 성능 숫자는 혼자서는 판정이 안 되고, 학습이 필요 없는 단순 규칙과 나란히 놓아야 판정이 된다

**한 줄 정리: 정확도 74%도 "전부 성공" 규칙(74.84%)을 못 이기면 0점이다.**

## □ 9.1.3 기준선 없이 성능을 말하지 않는다

○ **기준선(baseline)** 은 학습이 필요 없는 단순 예측 규칙이다. 딥러닝 모델의 성적은 이 기준선과 같은 테스트 구간·같은 지표로 비교해야만 뜻을 갖는다

○ 이 실습의 기준선은 세 개다. 셋 다 학습할 숫자가 0개다

– **persistence(직전 값 반복)**: 입력 창의 마지막 관측값을 앞으로 24시간 내내 그대로 쓴다. 값이 천천히 변하는 계열에서 강하다

– **seasonal_24h(어제 같은 시각)**: 24시간 전 값을 시각별로 그대로 가져온다. 하루 주기가 뚜렷한 계열에서 강하다

– **moving_avg_24h(최근 24시간 평균)**: 마지막 24시간의 평균 하나를 24시간 내내 쓴다. 잡음이 큰 계열에서 강하다

○ 실습 코드(핵심 부분, 전체는 `9-3-train-evaluate.py`)

```python
last_value = X_test[:, -1, 0]                       # 창의 마지막 관측값
prev_day   = X_test[:, -24:, 0]                     # 어제 같은 시각 24개
mean_24h   = X_test[:, -24:, 0].mean(axis=1)        # 최근 24시간 평균

preds = {
    'persistence':    np.repeat(last_value[:, None], 24, axis=1),
    'seasonal_24h':   prev_day,
    'moving_avg_24h': np.repeat(mean_24h[:, None], 24, axis=1),
}
```

○ 실행 결과(`results/9-3-train-evaluate.log` 발췌)

```

  - moving_avg_24h  RMSE   3935.1 MW | MAE   3299.8 MW | MAPE  5.22%
```

– 해석: "어제 같은 시각" 규칙이 MAE 2,023.3 MW로 가장 낮다. 이 계열의 하루 주기가 그만큼 강하다는 뜻이고, 이제 딥러닝 모델은 이 2,023.3을 이겨야 채택된다

○ 판정 눈금 세 단계

– 모델의 MAE가 최고 기준선보다 낮지 않으면 그 모델은 보고하지 않는다

– 낮더라도 개선폭이 5% 미만이면, 학습·배포·감시에 드는 비용을 감당할 만한지 따로 따진다

– 개선폭이 비정상적으로 크면(예: 절반 이하로 떨어짐) 좋아하기 전에 9.2.2의 누수 점검부터 통과시킨다

**한 줄 정리: 기준선을 먼저 세운다. 기준선 없는 성능 숫자는 판정이 불가능하다.**

## □ 9.2.1 lookback과 horizon — 시계열을 학습용 표로 자른다

○ 시계열은 그대로는 학습에 넣을 수 없고, "입력 하나 → 출력 하나" 꼴로 잘라야 한다. 이때 정하는 두 숫자가 **lookback(과거를 몇 시간 볼지)** 과 **horizon(미래를 몇 시간 맞출지)** 이며, 모델 구조보다 성능에 더 크게 작용하는 경우가 많다

○ 이 실습의 세 값

– lookback 168: 일주일치 시간별 값을 본다. 하루 주기와 주중·주말 차이를 한 창 안에 모두 담기 위한 값이다

– horizon 24: 다음 24시간을 한 번에 맞춘다. 다음 날 발전 계획을 짜는 의사결정 주기에 맞춘 값이다

– stride(창을 미는 간격) 6: 창을 1시간씩 밀면 이웃한 두 창이 168칸 중 167칸을 공유해 정보는 거의 늘지 않고 학습 시간만 늘어난다. 6시간씩 밀면 시퀀스 수가 17,161개에서 2,861개로 줄어든다

○ lookback을 늘리면 대가가 있다. 앞쪽 168시간은 입력으로만 쓰이고 정답이 없는 구간이 되므로, 창을 키울수록 잘라낼 수 있는 학습 표본 수 자체가 줄어든다

○ 실습 코드(핵심 부분, 전체는 `9-1-data-preparation.py`)

```python
def create_sequences(data, seq_length=168, pred_length=24, stride=6):
    X, y = [], []
    for i in range(0, len(data) - seq_length - pred_length + 1, stride):
        X.append(data[i:i + seq_length])                                # 과거 168시간
        y.append(data[i + seq_length:i + seq_length + pred_length, 0])  # 다음 24시간 수요
    return np.array(X), np.array(y)
```

○ 실행 결과(`results/9-1-data-preparation.log` 발췌)

```
  - 총 시간: 17,520 시간 (2023-01-01 ~ 2024-12-30)
  - 평균 수요: 66700 MW / 최대 83311 MW / 최소 51121 MW
  - 입력 시퀀스 형태: (2861, 168, 19)
  - 타겟 시퀀스 형태: (2861, 24)
  - 해석: 2,861개 샘플, 각 168시간 입력 → 24시간 예측
```

– 해석: (2861, 168, 19)의 세 숫자는 시퀀스 개수, lookback 길이, 특징 개수다. 특징 19개는 수요 본체, 외생 변수(기온·태양광·풍력·정책 활성화 여부), 순환 인코딩한 시각·요일·월, 시차 특징(24·48·168시간 전 수요), 이동 통계(24·168시간 평균·표준편차)로 이루어진다

○ 판정 눈금: ① 시퀀스가 1,000개 아래로 떨어지면 lookback이나 stride가 과한 것이므로 줄인다 ② 특징 수가 시퀀스 수에 비해 지나치게 많으면 과적합이 먼저 온다 ③ horizon을 늘렸을 때 오차가 급히 커지면 그 horizon은 예측 가능 범위 밖이며, 이 판정은 9.5.4의 시계별 오차 곡선으로 한다

**한 줄 정리: lookback은 최장 주기를 담을 만큼, horizon은 의사결정 주기만큼. 창을 키우면 표본이 준다.**

## □ 9.2.2 시간순 분할과 데이터 누수

○ **데이터 누수(leakage)** 는 미래 정보가 학습에 섞이는 것이다. 누수가 있으면 시험 성적은 좋아지지만 실전 성능은 그대로다. 시험 전에 정답지를 잠깐 본 점수가 실력이 아닌 것과 같은 구조인데, 다른 점이 하나 있다 — 정답지를 본 사실은 본인이 알지만, 누수는 코드 몇 줄에 숨어 있어 결과만 보고는 알아채기 어렵다

○ 시계열에서 자주 나오는 누수는 세 가지다

– 전체 기간으로 **정규화** 기준을 잡음: 정규화란 단위가 다른 값들을 비슷한 범위로 맞추는 일인데, 그 기준(중앙값 등)을 전체 자료로 계산하면 테스트 구간의 분포가 훈련에 새어 든다

– 무작위 셔플 분할: 순서를 섞어 나누면 훈련 자료 사이사이에 미래 시점이 끼어들어, "과거와 미래를 동시에 보고 가운데를 채우는" 더 쉬운 문제로 바뀐다

– 미래를 포함한 이동 통계: 뒤쪽 값을 함께 쓰는 통계(중심 이동평균 등)를 특징으로 넣으면 정답의 일부를 입력에 넣는 셈이 된다

○ 대응은 두 단계다. 정규화 기준을 훈련 구간(앞 70%)만으로 잡아 전체에 적용하고, 시퀀스를 시간 순서 그대로 **학습/검증/테스트**(공부용/중간점검용/최종시험용)로 자른다

○ 실습 코드(핵심 부분, 전체는 `9-1-data-preparation.py`)

```python
fit_end = int(n_rows * 0.7)                          # 훈련 구간 경계
scaler = RobustScaler()                              # 중앙값·사분위 범위 기준 정규화
scaler.fit(df_clean[feature_cols].iloc[:fit_end])    # 앞 70%로만 기준을 잡는다
data_scaled = scaler.transform(df_clean[feature_cols])

train_end = int(n_seq * 0.7)                         # 훈련: 가장 오래된 구간
val_end   = int(n_seq * 0.85)                        # 검증: 그다음 / 테스트: 최신 구간
```

○ 실행 결과(`results/9-1-data-preparation.log` 발췌)


– 해석: 중앙값 66,409.8과 IQR 7,425.1은 훈련 구간에서만 계산한 값이고, 예측값을 MW 단위로 되돌릴 때도 이 두 값을 그대로 쓴다. 분할은 훈련 2,002 / 검증 429 / 테스트 430으로, 테스트가 가장 최신 구간이다

○ 판정 눈금: 테스트 MAPE(오차를 실제값으로 나눈 백분율)가 1% 아래로 나오면 성능을 믿기 전에 누수부터 의심한다. 정규화를 전체 자료로 했는지, 셔플이 들어갔는지, 특징에 정답 시점 이후 정보가 있는지 세 곳을 먼저 확인한다. 반대로 검증 오차와 테스트 오차의 차이가 크면 시간이 지나며 관계가 바뀐 것이므로 9.5.5의 드리프트 점검으로 넘어간다

**한 줄 정리: 정규화 기준은 훈련 구간만으로, 분할은 시간 순서 그대로. 성능이 너무 좋으면 코드부터 되짚는다.**

## □ 9.2.3 예측과 인과는 다르다 — 반사실 실습

○ 예측은 "내일 수요가 얼마인가"에 답하고, 인과는 "캠페인 때문에 수요가 얼마나 줄었는가"에 답한다. 후자의 비교 대상인 "캠페인이 없었을 때의 수요"는 관측되지 않으므로, 둘은 애초에 다른 질문이다

○ 둘을 잇는 장치가 **반사실(counterfactual) 예측**이다. 개입이 없었다는 조건으로 예측을 다시 만들어, 실제 관측값과의 차이를 효과의 후보로 본다. 불확실성은 재표집(부트스트랩)으로 신뢰구간을 만들어 붙인다

○ 실습에서는 가장 단순한 반사실 — 개입 전 구간의 직선 추세가 개입 후에도 이어진다는 가정 — 을 일부러 써 본다. 데이터는 1년치 합성 계열(기저 60,000, 1년·하루 주기, 잡음)에 60% 지점부터 **참 효과 +600을 심은** 것이다

○ 실습 코드(핵심 부분, 전체는 `9-counterfactual-with-stats.py`)

```python
without_policy = _fit_pretrend_counterfactual(series, intervention_idx)  # 개입 전 직선 추세 연장
with_policy = series.copy()
with_policy[intervention_idx:] += 600.0                                  # 참 효과 +600을 심는다

policy_effect = with_policy[start:end] - without_policy[start:end]       # 개입 후 30일 비교
ci_lower, ci_upper = np.percentile(bootstrap_effects, [2.5, 97.5])       # 부트스트랩 1,000회
```

○ 실행 결과(`results/9-counterfactual-with-stats.log`)

```
- 평균 정책 효과: -2,481.76
- 95% CI (bootstrap): [-2,626.21, -2,339.37]
- t-statistic: -33.423
- p-value (one-sided, H1: effect > 0): 1.000000
- 유의 여부(p<0.05): False
```

– 해석: 심어 둔 참 효과는 +600인데 추정치는 −2,481.76이다. 크기만 틀린 것이 아니라 **부호까지 뒤집혔다**. 원인은 반사실 쪽에 있다. 개입 전 구간을 직선으로 근사해 연장했는데, 실제 계열은 1년 주기 곡선을 그리며 내려가는 국면이었으므로, 직선 반사실이 실제보다 높은 "가상의 수요"를 만들었고 그 차이가 전부 효과로 잘못 계산되었다

– 신뢰구간 [−2,626, −2,339]가 0에서 멀리 떨어져 있다는 사실도 경고다. 반사실 모형이 틀리면 통계적 확신은 틀린 값 주위에서 좁게 잡힌다. 좁은 신뢰구간은 모형이 맞다는 증거가 아니다

○ 판정 눈금: 반사실 예측을 쓰기 전에 **개입 전 구간에서 그 모형의 예측 오차부터 잰다**. 사전 기간 오차(MAE)가 검출하려는 효과 크기와 비슷하거나 크면, 그 반사실로 잰 효과는 보고하지 않는다

– 판정 연습(가상의 수치다): 기대 효과가 500인데 반사실 모형의 사전 기간 MAE가 각각 80, 450, 2,000이라면? 80은 진행, 450은 효과와 오차가 같은 크기이므로 보류, 2,000은 그 모형을 쓰지 않는다

○ 실무 규칙: 예측 모델의 반사실 값은 효과 크기의 1차 추정으로만 쓰고, 최종 판단은 2~6장에서 배운 이중차분법·합성통제·도구변수 같은 식별 설계로 확인한다. 두 접근의 결과가 크게 다르면 예측 모델 쪽을 신뢰하지 않는다

**한 줄 정리: 반사실 모형이 계절 곡선을 못 담으면, 심어 둔 +600이 −2,482로 나온다. 사전 기간 오차부터 잰다.**

## □ 9.3.1 순서를 살려 읽는 구조 — 은닉 상태

○ 9.2.1에서 만든 입력 하나는 (168, 19) 크기의 표다. 이 표를 한 줄로 펼쳐 일반 신경망에 넣으면 168×19 = 3,192개의 값이 순서 없이 나열된 것으로 취급되어, 첫 시각과 마지막 시각의 구분이 사라진다

○ 순환신경망(RNN)은 표를 한 번에 넣지 않고 **한 시점씩 차례로** 읽는다. 시점마다 두 가지를 섞어 새 요약을 만든다

– 지금 들어온 값(이번 시각의 수요·기온 등)과, 직전까지의 요약. 이 요약 숫자 묶음이 **은닉 상태(hidden state)** 이며, 다음 시점의 계산으로 넘겨진다

– 이전 시점의 정보가 은닉 상태를 타고 다음 계산에 넘어가므로, 순서가 계산 구조 안에 살아남는다

○ 섞는 데 쓰는 가중치는 모든 시점에서 같은 것을 공유한다. 그래서 창이 168시간이어도 시점 수만큼 가중치가 늘어나지 않는다

○ 판정 눈금: 학습 곡선에서 손실이 처음 몇 에포크 만에 평평해지고 검증 MAE가 기준선 수준에 머물면, 순서 정보가 예측에 쓰이지 못하고 평균 수준의 답만 나오고 있을 가능성이 크다. 층을 늘리기 전에 lookback이 과한지, 특징들의 크기 범위가 서로 많이 다른지부터 확인한다

**한 줄 정리: RNN은 과거의 요약(은닉 상태)을 다음 시점으로 넘겨, 순서를 계산 구조에 남긴다.**

## □ 9.3.2 기울기 소실 — 먼 과거가 지워진다

○ 168시간 전의 정보가 지금 예측에 반영되려면, 학습 신호(오차를 고치라는 신호)가 168단계를 거슬러 전달되어야 한다. 이 전달은 단계마다 값을 곱하는 구조라서 문제가 생긴다

– 단계마다 1보다 작은 수가 곱해지면 신호가 급격히 줄어든다. 예를 들어 매 단계 0.9배가 되면, 50단계 뒤에는 0.9를 50번 곱한 약 0.005만 남는다. 먼 과거의 정보가 학습에 거의 반영되지 못하는 이 현상이 **기울기 소실**이다

– 반대로 단계마다 1보다 큰 수가 곱해지면 신호가 폭발적으로 커진다(기울기 폭발)

○ 실무에서 이 한계는 시퀀스 길이 50~100 시점부터 드러난다. 실습의 lookback 168은 이미 그 범위를 넘으므로, 기본 RNN으로는 일주일 전 패턴이 학습에 제대로 반영되지 않는다

○ 두 증상은 출력에서 다르게 나타나고, 처방도 다르다

– 손실이 NaN으로 바뀌거나 갑자기 수십 배로 튀면 폭발이다. 기울기 크기에 상한을 거는 조치(클리핑)를 쓴다

– 손실이 초반에만 조금 내려가고 그 뒤 움직이지 않으면 소실이다. 완화 기법을 덧대기보다 다음 절의 LSTM·GRU로 구조를 바꾼다

**한 줄 정리: 0.9를 50번 곱하면 0.005다. 긴 창의 먼 과거는 기본 RNN에서는 지워진다.**

## □ 9.4.1 LSTM — 지울 것과 남길 것을 정하는 문

○ 기울기 소실은 정보가 매 시점 같은 경로에서 눌려 지나가기 때문에 생긴다. **LSTM**은 은닉 상태와 별도로, 정보를 거의 그대로 통과시키는 통로(셀 상태)를 하나 더 두어 이 문제를 다룬다

○ 셀 상태의 값은 세 개의 **게이트**를 거쳐 바뀐다. 게이트는 0과 1 사이의 비율을 내는 계산 단위다

– 망각 게이트: 이전까지 담아 온 값 중 얼마를 지울지 정한다. 0이면 전부 지우고 1이면 그대로 둔다

– 입력 게이트: 이번 시점의 새 정보를 얼마나 담을지 정한다

– 출력 게이트: 담긴 값 중 어느 부분을 이번 시점의 출력으로 내보낼지 정한다

○ 작은 숫자로 보면 이렇다. 셀 상태의 한 칸이 5이고 망각 게이트가 0.9, 입력 게이트가 0.2, 새 정보 후보가 3이라면, 새 값은 5×0.9 + 3×0.2 = 4.5 + 0.6 = 5.1이다

– 곱하고 더하는 계산뿐인 이 통로 덕분에, 게이트가 1에 가까운 구간에서는 학습 신호가 여러 단계를 거슬러도 크게 줄지 않는다

○ 전력 수요에 붙여 보면: 3개월 전 한파의 정보는 망각 게이트 값이 작아지며 비중이 점차 줄고, 새로 시작된 정책의 수준 변화는 입력 게이트를 거쳐 셀 상태에 오래 남는다

**한 줄 정리: LSTM은 지울 비율과 남길 비율을 데이터에서 배워, 긴 주기의 정보를 통로에 남긴다.**

## □ 9.4.2 GRU — 문을 둘로 줄인 구조

○ LSTM은 게이트가 셋이라 학습할 숫자(파라미터)가 많다. **GRU**는 셀 상태를 따로 두지 않고 은닉 상태 하나로 합친 뒤 게이트를 둘로 줄인 구조다

– 업데이트 게이트가 "지우기"와 "새로 담기"를 한 번에 정하고, 리셋 게이트가 새 후보를 만들 때 과거를 얼마나 반영할지 정한다. 최종 갱신은 과거 요약과 새 후보의 가중평균이다

○ 파라미터 수 차이는 `9-2-lstm-model.py`가 실제 모델로 확인한다. 이 스크립트는 학습 전 단계로, 세 모델의 층 구성과 파라미터 수만 확인한다

○ 실행 결과(`results/9-2-lstm-model.log` 발췌)

```
  1. LSTM+Attention: LSTM 3층(128,64,32) + 어텐션 1층, 파라미터 145,496
  2. LSTM:           LSTM 2층(128,64),            파라미터 130,904
  3. GRU:            GRU  2층(128,64),            파라미터 100,184

  LSTM 1층: 4 x (128 x (19 + 128) + 128) = 75,776
  GRU  1층: 3 x (128 x (19 + 128) + 128 x 2) = 57,216
  GRU가 LSTM보다 23.5% 적다 (게이트 3개 대 4개)
```

– 해석: 같은 크기(128, 64 유닛)로 쌓아도 GRU 모델의 파라미터는 100,184개로 LSTM 모델(130,904개)보다 23.5% 적다. 같은 계산 단위 안에 문이 하나 적기 때문이며, 파라미터가 적으면 학습 한 바퀴가 그만큼 가벼워진다

○ 선택 규칙: lookback이 100 시점 이하이고 실험을 빠르게 반복해야 하면 GRU를 먼저 쓰고, 수백 시점 이상의 긴 의존이 중요하면 LSTM을 쓴다. 실습처럼 lookback 168의 경계 구간에서는 두 모델을 모두 돌려 같은 테스트 구간에서 비교하는 것이 확실하다

**한 줄 정리: GRU는 문 하나를 줄여 파라미터를 23.5% 아꼈다. 경계 구간에서는 둘 다 돌려 비교한다.**

## □ 9.4.3 모델 세 개를 학습시킨다

○ 지금까지 만든 것은 자료와 기준선뿐이다. 이제 딥러닝 모델을 실제로 학습시켜, 9.1.3의 판정 기준에 넣을 숫자를 얻는다

○ 구조가 다른 모델 세 개를 같은 자료로 학습시킨다

– LSTM: LSTM 2층(128, 64) 뒤에 Dense 64와 Dense 24. 가장 단순한 비교 대상이다

– GRU: 같은 크기의 GRU 2층. LSTM과 구조만 다르고 규모는 비슷하다

– LSTM+어텐션: LSTM 3층(128, 64, 32) 뒤에 멀티헤드 어텐션(헤드 4개)을 얹어, 168개 시점 중 어디에 큰 가중치를 둘지도 함께 학습하게 한다

○ 세 모델 모두 출력층이 Dense(24)라서 24시간을 **한 번에** 내놓는다. 한 시점씩 예측해 그 값을 다시 입력으로 넣는 방식이 아니라는 점이, 뒤에서(9.5.4) 오차를 읽을 때 중요해진다

○ 실습 코드(핵심 부분, 전체는 `9-2-lstm-model.py`, `9-3-train-evaluate.py`)

```python
model = keras.Sequential([
    keras.layers.LSTM(128, return_sequences=True,
                      input_shape=(seq_length, n_features), dropout=0.2),
    keras.layers.LSTM(64, dropout=0.2),
    keras.layers.Dense(64, activation='relu'),
    keras.layers.Dropout(0.2),
    keras.layers.Dense(pred_length),        # 24시간을 한 번에 출력
])

history = model.fit(
    X_train, y_train, validation_data=(X_val, y_val),
    epochs=20, batch_size=32,
    callbacks=[
        keras.callbacks.EarlyStopping(monitor='val_loss', patience=20,
                                      restore_best_weights=True),
        keras.callbacks.ReduceLROnPlateau(monitor='val_loss', factor=0.5,
                                          patience=10, min_lr=1e-6),
    ],
)
```

– 두 장치의 역할: EarlyStopping은 검증 손실이 20 에포크 동안 나아지지 않으면 학습을 멈추고 가장 좋았던 가중치로 되돌리며, ReduceLROnPlateau는 검증 손실이 10 에포크 정체하면 학습률(한 번에 고치는 양)을 절반으로 낮춘다

○ 실행 결과(`results/9-3-train-evaluate.log` 발췌)


– 검증 손실이 훈련 손실보다 낮게 나온 점은 이상이 아니다. 드롭아웃(학습 중 일부 연결을 무작위로 끄는 장치)이 훈련 손실을 잴 때만 켜져 있어, 훈련 쪽이 더 어렵게 측정되기 때문이다

○ 판정 눈금 세 가지

– 검증 손실이 훈련 손실의 두 배를 넘으면 과적합(훈련 자료 암기)이므로, 드롭아웃 비율을 올리거나 층을 줄인다

– 두 손실이 모두 높은 채 멈췄으면 학습 부족이므로 에포크 상한을 올린다

– 조기 종료 없이 상한(20 에포크)까지 갔다면 아직 개선 여지가 남았다는 뜻이므로, 상한을 늘려 다시 돌린다

**한 줄 정리: 세 모델을 같은 자료로 학습시켜, 기준선과 같은 시험대에 올릴 숫자를 만들었다.**

## □ 9.5.1 지표 세 개를 나눠 읽는다

○ 하나의 숫자로 성능을 요약하면 실패 지점이 가려진다. 평균 오차는 작은데 여름 피크에서만 크게 어긋나는 모델은, 발전 계획 관점에서 평균 오차가 조금 더 큰 모델보다 위험하다

○ 세 지표는 오차를 서로 다르게 센다

– **RMSE**: 오차를 제곱해 평균 낸 뒤 제곱근을 씌운다. 제곱 때문에 큰 오차 하나가 값을 크게 끌어올리므로, 드물지만 치명적인 실패를 잡는 데 쓴다

– **MAE**: 오차 절댓값의 평균. 모든 오차를 같은 비중으로 세므로 평소 수준의 오차를 대표한다

– **MAPE**: 오차를 실제값으로 나눈 백분율의 평균. 단위가 다른 계열끼리 비교할 때 쓰되, 실제값이 0에 가까운 구간에서는 값이 폭주하므로 주의한다

○ 실습 코드(핵심 부분, 전체는 `9-3-train-evaluate.py`)

```python
err  = y_true - y_pred
rmse = float(np.sqrt(np.mean(err ** 2)))
mae  = float(np.mean(np.abs(err)))
mape = float(np.mean(np.abs(err / y_true)) * 100)
```

○ 판정은 RMSE와 MAE의 **비율**로 한다. 1.2 안쪽이면 오차가 고르게 퍼진 것이고, 1.5를 넘으면 특정 구간에 큰 오차가 몰려 있다는 신호이므로 오차 분포 그림에서 어느 쪽 꼬리가 두꺼운지 확인한다

– 실측 예: 9.1.3의 persistence 기준선은 RMSE 5,474.1, MAE 4,451.4로 비율 1.23이다. 오차가 크긴 하지만 고르게 퍼져 있다는 뜻이다

○ 판정 연습(가상의 수치다): 두 모델의 (RMSE, MAE)가 각각 (1,300, 1,100)과 (2,400, 1,150)이라면?

– 비율은 1.18과 2.09다. MAE는 거의 같지만 두 번째 모델은 큰 오차가 특정 구간에 몰려 있으므로, 평균만 보고 채택하면 피크 구간에서 사고가 난다

**한 줄 정리: MAE는 평소 오차, RMSE는 큰 실패. 비율이 1.5를 넘으면 오차가 몰린 곳부터 찾는다.**

## □ 9.5.3 학습 곡선으로 과적합을 판정한다

○ 테스트 성능이 나쁠 때 원인은 두 갈래다. 덜 배웠거나(학습 부족), 훈련 자료를 외웠거나(과적합)다. 두 경우의 처방이 반대이므로 먼저 구분해야 한다

○ `results/9-3-learning-curves.png`는 에포크별 손실과 MAE를 훈련(실선)·검증(점선)으로 나눠 그린다. 세 가지 모양으로 판정한다

– 두 곡선이 함께 내려가다 검증 곡선만 올라가면 과적합이다. 올라가기 직전 에포크가 최적점이며, 조기 종료가 그 지점의 가중치를 되돌려 준다. 드롭아웃을 올리거나 층을 줄인다

– 두 곡선이 모두 높은 곳에서 평평하면 학습 부족이다. 에포크 상한을 올리거나 모델 크기를 키운다

– 검증 곡선이 위아래로 심하게 흔들리면 학습률이 크거나 배치가 작은 것이다. 학습률 감소 장치가 걸리는지 확인하고, 걸리지 않으면 초기 학습률을 낮춘다

○ 이 실습의 실행에서는 훈련 손실보다 검증 손실이 낮게 나왔다(9.4.3의 로그). 드롭아웃은 훈련 중에만 켜져 훈련 손실을 높게 재기 때문이며, 이 방향의 차이는 과적합 신호가 아니다

**한 줄 정리: 검증 곡선이 올라서면 과적합, 둘 다 평평하면 학습 부족. 처방이 반대이니 구분부터 한다.**

## □ 9.5.4 다단계 예측과 오차 누적

○ 1시간 앞과 24시간 앞은 난도가 다르다. 발전 계획은 24시간 전체를 요구하지만, 뒤쪽 시계의 예측이 기준선보다 나쁘다면 그 구간은 모델 대신 기준선을 쓰는 편이 낫다. 이 판단에는 시계별로 나눈 오차가 필요하다

○ 다단계 예측을 만드는 방식은 두 가지다

– 재귀 방식: 1시간 앞을 예측하고 그 예측값을 입력에 되넣어 다음 1시간을 예측하기를 24번 반복한다. 모델은 하나면 되지만 앞 단계의 오차가 뒤 단계의 입력으로 들어가 오차가 굴러간다

– 직접 방식: 출력층 Dense(24)로 24개 값을 한 번에 내놓는다. 실습의 세 모델이 모두 이 방식이며, 예측값을 입력으로 되쓰지 않으므로 오차가 굴러갈 경로가 없다

○ 직접 방식이어도 뒤쪽 시계의 오차는 대체로 더 크다. 오차가 굴러서가 아니라, 24시간 뒤의 불확실성 자체가 1시간 뒤보다 크기 때문이다. 두 원인의 구분이 이 절의 요점이다

○ 실습 코드(핵심 부분, 전체는 `9-3-train-evaluate.py`)

```python
# 시계(h)별 MAE: 축 0은 표본, 축 1은 예측 시계(1~24시간 앞)
mae_by_h  = np.mean(np.abs(y_true - y_pred), axis=0)                     # (24,)
base_by_h = np.mean(np.abs(y_true - baselines['seasonal_24h']), axis=0)
```

○ 판정 눈금 — `9-3-baseline-vs-deep.png`의 (d) 선 모양으로 세 가지를 가른다

– 모델 곡선이 24시간 내내 기준선 아래에 있으면 24시간 전체를 모델 예측으로 쓴다

– 어느 시계 h에서 모델 곡선이 기준선 곡선 위로 올라서면, h 시간까지만 모델을 쓰고 그 뒤는 기준선으로 대체하거나 예측 갱신 주기를 h로 줄인다. 예를 들어 12시간째에 교차하면 반나절마다 예측을 다시 만드는 운영으로 바꾼다

– 곡선이 처음부터 평평하면 시계 구분 없이 비슷한 값만 나오고 있다는 신호이므로, (a) 그림에서 예측 곡선이 하루 주기를 재현하는지 함께 확인한다

○ 결정으로 옮길 때는 시계별 오차를 물량으로 환산한다. 6시간째 MAE와 24시간째 MAE가 다르면 예비력도 시계별로 다르게 잡아야 하며, 모든 시계에 같은 예비력을 두면 앞쪽에서는 과잉, 뒤쪽에서는 부족이 동시에 생긴다

**한 줄 정리: 시계별 오차 곡선이 기준선과 만나는 지점이, 예측을 몇 시간까지 쓸지 정하는 눈금이다.**

## □ 9.5.5 드리프트 — 모델은 배포한 날부터 낡는다

○ 요금 체계가 바뀌거나 대형 수용가가 들어오거나 기후 패턴이 달라지면, 학습 당시의 입력-출력 관계가 더는 성립하지 않는다. 이 변화가 **드리프트(drift)** 다

○ 감시 대상은 두 종류로 나눈다

– 입력 분포 변화: 기온·발전량 같은 입력 변수의 분포가 학습 당시와 달라진 경우. 정답이 나오기 전에도 감지할 수 있다

– 성능 저하: 입력 분포는 비슷한데 오차만 커진 경우. 정답이 확정된 뒤에야 보이지만, 재학습 판단의 직접 근거가 된다

○ 실습에서는 테스트 구간을 시간 순서로 3등분해 구간별 MAE를 비교한다. 테스트가 가장 최신 자료이므로, 전반부에서 후반부로 갈수록 오차가 커지면 모델이 최근 자료에서 약해지고 있다는 신호다

○ 실습 코드(핵심 부분, 전체는 `9-3-train-evaluate.py`)

```python
a, b = int(n_samples * 0.3), int(n_samples * 0.7)
mae_1 = float(np.mean(np.abs(y_true[:a]  - y_pred[:a])))    # 전반부
mae_2 = float(np.mean(np.abs(y_true[a:b] - y_pred[a:b])))   # 중반부
mae_3 = float(np.mean(np.abs(y_true[b:]  - y_pred[b:])))    # 후반부
```

○ 실행 결과(`results/9-3-train-evaluate.log` 발췌 — 최고 모델 GRU 기준)

```
테스트 구간 3등분 MAE...
  - 전반부 MAE: 1452.4 MW
  - 중반부 MAE: 1480.7 MW
  - 후반부 MAE: 1426.7 MW
```

– 해석: 가장 큰 값(1,480.7)과 가장 작은 값(1,426.7)의 차이가 약 3.8%로 10% 안쪽이다. 아래 규칙의 첫 번째 경우, 곧 안정 상태이므로 예정된 주기에 맞춰 재학습하면 된다

○ 판정 규칙은 미리 숫자로 정해 두고 그대로 따른다

– 세 값이 서로 10% 안쪽 차이면 안정 상태다. 예정된 주기(예: 분기)에 맞춰 재학습한다

– 후반부 MAE가 전반부보다 20% 이상 크면 성능 저하로 판정하고, 최근 자료를 포함해 재학습한 뒤 기준선과 다시 비교한다

– 후반부 MAE가 최고 기준선의 MAE를 넘어서면 모델 사용을 중지하고 기준선으로 되돌린다. 재학습이 끝나 기준선을 다시 이길 때까지 모델을 쓰지 않는다

○ 판정 연습(가상의 수치다): 3등분 MAE가 전반부 1,100, 중반부 1,150, 후반부 1,600 MW라면?

– 후반부가 전반부보다 45% 크므로 성능 저하다. 최근 자료를 포함해 재학습한다. 다만 후반부 1,600이 기준선 MAE(이 실습에서는 2,023.3)보다 아직 낮으므로, 재학습이 끝날 때까지 모델을 계속 쓸 수는 있다

○ 주의: 이 3등분은 시간 3등분이지 정책 단계가 아니다. 실습 데이터의 정책 효과는 전체 시계열의 50% 지점부터 시작하므로, 뒤 15%인 테스트 구간은 전부 정책 시행 이후다. 세 구간의 오차 차이를 정책 도입기·정착기의 차이로 읽으면 틀린 결론이 나온다

**한 줄 정리: 재학습·사용중지 기준을 숫자로 미리 적어 두고, 구간별 오차가 그 선을 넘는지만 본다.**

## □ 9.5.6 어텐션 가중치는 무엇을 알려주는가

○ **어텐션**은 입력 창의 각 시점에 가중치를 매기고 합이 1이 되도록 맞추는 계산이다. 창 길이가 168이므로, 모든 시점에 똑같이 배분하면 시점 하나의 가중치는 1/168 = 0.0060이다. 이 값이 읽기의 기준선이 된다

○ 실행 결과(`results/9-2-lstm-model.log` 발췌 — 학습 전)

```
  - 평균 어텐션 점수 범위: [0.0060, 0.0060]
  - 균등 배분값 1/168 = 0.0060
  - 학습 전이라 168개 시점에 가중치가 거의 고르게 퍼져 있다
```

– 해석: 학습 전에는 가중치가 균등 배분값에 붙어 있다. 학습 뒤에도 상위 시점의 가중치가 0.0060 근처에 머문다면, 어텐션이 특정 시점을 가려내지 못한 것이다

○ 실행 결과(`results/9-3-train-evaluate.log` 발췌 — 학습 후)

```
  - 균등 배분값 1/168 = 0.0060
  - 가중치가 높은 시점 5개 (창의 시작을 0으로 센 위치):
    1. 2번째 시점 (점수: 0.0911)
    2. 1번째 시점 (점수: 0.0729)
    3. 3번째 시점 (점수: 0.0575)
    4. 0번째 시점 (점수: 0.0518)
    5. 4번째 시점 (점수: 0.0175)
```

– 해석: 상위 5개가 모두 창의 시작인 0~4번째 시점, 곧 지금부터 164~168시간 전(일주일 전 부근)이다. 최고 가중치 0.0911은 균등값 0.0060의 약 15배로, 학습 뒤에는 가중치가 특정 시점에 뚜렷하게 몰렸다

– 일주일 전 같은 요일·같은 시각 부근에 몰린 결과는 이 계열의 일주일 주기와 맞는다. 다만 9.5.2의 표에서 어텐션 모델의 오차가 셋 중 가장 컸으므로, 이 데이터에서는 그 시차를 이미 명시적 특징(demand_lag_168h)으로 넣은 단순 모델로 충분하다는 판정이 선다

○ 판정 눈금 두 가지

– 상위 시점의 가중치가 균등값 근처에 머물면, 어텐션을 뺀 단순 모델과 성능을 비교해 굳이 붙일 필요가 있는지 확인한다

– 상위 시점이 창의 끝(가장 최근)이나 24시간 전, 168시간 전 부근에 몰리면 도메인 지식과 맞는 결과다. 그 시차를 명시적 특징으로 넣은 더 단순한 모델로 같은 성능이 나오는지 시험한다

○ 어텐션 가중치는 "모델 계산에서 어느 시점의 비중이 컸는가"까지만 알려준다. 설명의 실마리이지 인과의 근거가 아니다

**한 줄 정리: 어텐션은 균등값 0.0060과 대조해 읽고, 설명의 실마리로만 쓴다.**

## □ 9.6.1 예측값을 결정 규칙으로 바꾼다

○ 예측값 자체는 결정이 아니다. "내일 오후 2시 수요 예측 66,000 MW"라는 숫자는 예비력을 얼마나 확보할지 정해 주지 않는다. 예측을 결정으로 옮기려면 틀렸을 때의 비용 구조가 필요하다

○ 전력 수요에서 두 방향의 오차는 비용이 다르다. 수요를 낮게 잡아 공급이 모자라면 정전 위험과 비상 발전 단가가 붙고, 높게 잡으면 연료비와 가동 비용이 낭비된다. 두 비용이 다르므로 예측값 그대로가 아니라 한쪽으로 여유를 둔 값을 쓴다

○ 절차는 세 단계다

– ① 9.5.4의 시계별 MAE로 각 시계의 오차 폭을 잡는다

– ② 부족 비용과 과잉 비용의 비율을 정한다. 이것은 통계가 아니라 정책·운영상의 결정이다

– ③ 두 값을 곱해 시계별 예비력 폭을 정하고, 시계가 길수록 폭을 넓힌다

○ 판정은 사후 점검으로 만든다. 한 달간 부족 발생 횟수와 과잉 확보량을 기록해, 부족이 목표 빈도보다 잦으면 폭을 넓히고 과잉이 계속 크면 좁힌다. 모델을 다시 학습하지 않고 결정 규칙만 고치는 조정이므로 반영이 빠르다

**한 줄 정리: 예측값에 비용 구조를 곱해야 결정이 된다. 결정 규칙의 조정은 재학습보다 빠르다.**

## □ 9.6.2 예측 모델로 인과를 말할 수 있는 조건

○ 9.2.3의 반사실 예측을 그대로 인과효과로 옮기면 세 가지가 걸린다

– 선택 편향과 교란: 정책은 무작위로 배정되지 않고 특정 지역·시점에 먼저 들어간다. 예측 모델은 과거 패턴을 재현할 뿐, 교란 변수를 자동으로 통제하지 못한다

– 지연 효과와 시간 가변성: 효과가 몇 달에 걸쳐 누적되거나 시간이 지나며 방향이 바뀔 수 있다. LSTM이 이런 패턴을 담을 수는 있어도, 지연 구조를 명시적으로 검증해 주지는 않는다

– 구조 변화: 팬데믹이나 급격한 연료 가격 변동처럼 학습 자료에 없던 충격이 오면 예측 자체가 무너진다. 이때 커진 오차를 정책 효과로 읽으면, 9.2.3에서 본 것처럼 부호까지 뒤집힐 수 있다

○ 그래서 규칙은 하나로 정리된다. **예측 성능이 좋다는 사실은 인과 주장의 근거가 아니다.** 정책 효과를 보고할 때는 2~6장의 식별 설계를 주 결과로 두고, 예측 모델의 반사실 값은 보조 근거로만 붙인다

**한 줄 정리: 잘 맞히는 모델과 옳은 인과 주장은 다른 물건이다. 식별 설계가 주, 반사실 예측은 보조다.**

## □ 9.6.3 긴 시퀀스와 새 아키텍처 — 상태공간모델과 Mamba

○ lookback을 168에서 수천 시점으로 늘려야 하는 문제도 있다. Transformer 계열은 모든 시점 쌍의 관계를 계산하므로 연산량이 시퀀스 길이의 제곱에 비례한다. 1,000시점이면 100만 번, 10,000시점이면 1억 번으로 늘어난다

○ Gu & Dao(2023)가 제안한 **Mamba**는 상태공간모델(State Space Model)을 딥러닝에 적용해 이 비용을 시퀀스 길이에 비례하는 수준으로 낮췄다

– 상태공간모델은 RNN처럼 시점마다 "지금 입력 + 직전 상태 → 새 상태"로 갱신하고 그 상태에서 출력을 만든다. 기존에는 이 결합 규칙이 모든 시점에서 고정이었는데, Mamba는 입력에 따라 규칙이 달라지게 만들어 중요한 시점의 정보를 더 강하게 남긴다

– 갱신 폭을 정하는 값이 입력에 따라 변해서, 값이 부드럽게 움직이는 구간에서는 상태가 천천히, 급변 구간에서는 빠르게 갱신된다

○ 실습 코드(핵심 부분, 전체는 `9-4-mamba-ssm.py` — 교육용 단순 구현)

```python
for t in range(length):
    # 상태 갱신: 새 상태 = (감쇠 비율) x 직전 상태 + (입력 비율) x 지금 입력
    state = deltaA_t * state + deltaB_t * x_t
    # 출력: 상태를 요약해 이번 시점의 출력을 만든다
    y_t = tf.reduce_sum(state * tf.expand_dims(C_t, -1), axis=-1)
```

– 이 스크립트는 현재 버전에서 실행 오류(케라스 그래프 모드에서 파이썬 루프 사용)가 나므로, 이 장에서는 실행 결과를 싣지 않고 구조만 읽는다

○ 시계열 분야에서는 사전학습 모델도 나오고 있다. MOMENT(2024), Chronos(2024), TimesFM(2024)은 대규모 시계열로 미리 학습해 도메인별 재학습 없이도 예측을 내놓는다

○ 판정 기준은 실용적으로 잡는다. lookback이 수백 시점 이하이면 LSTM·GRU로 충분하므로 새 구조를 먼저 시도할 이유가 없다. 새 아키텍처든 사전학습 모델이든, 9.1.3의 기준선 세 개와 같은 테스트 구간에서 비교하는 절차는 그대로 적용한다. 기준선을 이기지 못하는 모델은 최신이라는 이유로 채택되지 않는다

**한 줄 정리: 새 구조도 시험대는 같다. 기준선과 같은 테스트 구간에서 비교하고 나서야 채택을 논한다.**

## □ 실무 적용 점검표

○ 기준선을 먼저 계산했는가. 학습 없는 규칙 두세 개를 같은 테스트 구간에서 계산해 적어 두었는가

○ lookback과 horizon의 근거를 적었는가. lookback은 계열의 최장 주기를 담는지, horizon은 의사결정 주기와 맞는지 확인했는가

○ 정규화 기준을 훈련 구간만으로 잡았는가

○ 분할에 셔플이 들어가지 않았는가. 훈련·검증·테스트가 시간 순서대로 놓였는가

○ 특징 중에 정답 이후 정보가 없는가. 이동 통계가 미래 값을 포함하지 않는지 정의를 확인했는가

○ 성능이 너무 좋으면 누수를 먼저 의심했는가

○ 시계별 오차를 확인하고, 예측을 몇 시간까지 쓸지 숫자로 정했는가

○ 재학습 규칙을 숫자로 정했는가. 어떤 지표가 몇 % 나빠지면 재학습하고, 어떤 값이면 사용을 중지하는가

○ 반사실 예측을 쓴다면 개입 전 구간에서 그 모형의 오차를 먼저 쟀는가

○ 인과 주장을 예측 성능으로 대신하지 않았는가. 정책 효과 보고에는 식별 설계를 주 결과로 두었는가

## □ 핵심 정리

| 주제 | 한 줄 요약 |
|---|---|
| 기준선 | 학습 없는 규칙 세 개를 먼저 계산하고, 못 이긴 모델은 보고하지 않는다 |
| lookback·horizon | 최장 주기와 의사결정 주기에 맞추되, 창을 키우면 표본이 준다 |
| 시간순 분할 | 셔플하지 않고, 정규화 기준도 훈련 구간만으로 잡는다 |
| 누수 | 성능이 지나치게 좋으면 모델을 칭찬하기 전에 코드를 되짚는다 |
| RNN의 한계 | 50~100 시점을 넘으면 학습 신호가 줄어 먼 과거가 반영되지 않는다 |
| LSTM·GRU | 게이트로 지울 비율과 남길 비율을 배워 긴 주기를 다룬다 |
| 다단계 예측 | 직접 방식이어도 뒤쪽 시계의 불확실성은 크다. 시계별로 오차를 나눠 본다 |
| 드리프트 | 구간별 오차로 감지하고, 재학습·사용중지 기준을 숫자로 미리 정한다 |
| 반사실 예측 | 반사실 모형이 틀리면 부호까지 뒤집힌다. 사전 기간 오차부터 잰다 |
| 예측과 인과 | 예측 성능이 좋다는 사실은 인과 주장의 근거가 되지 못한다 |

○ 이 장의 판정 규칙 세 가지

– **기준선 비교가 첫 관문이다.** 이 관문을 통과하지 못한 모델의 나머지 결과는 읽지 않는다

– **시계별로 잘라 판정한다.** 24시간 전체가 아니라, 기준선과 교차하는 시계까지만 모델을 쓴다

– **반사실 예측은 사전 기간 오차로 자격을 검사한다.** 자격 없는 반사실로 잰 효과는 크기도 부호도 믿을 수 없다
