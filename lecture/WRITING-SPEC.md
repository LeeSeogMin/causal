## 1. 목적

`docs/`의 내용을 학부생이 **원리를 이해하고 실무에 적용할 수 있도록** 다시 쓴다.

- 목표는 "쉽게 읽히는 것"이 아니라 **"읽고 나서 직접 해 볼 수 있는 것"**이다.
- 세부 수학 유도를 요구하지 않는다. 수식이 필요하면 각 항이 무엇을 뜻하는지 말로 풀고, 숫자를 대입해 따라간다.
- 방법의 이름을 외우는 것이 아니라 **어떤 상황에서 어느 방법을 고르고, 나온 숫자를 어떻게 읽는지** 판단할 수 있게 한다.

## 2. 65분 × 2파트 구조 (필수)

한 장은 **65분짜리 두 파트**로 나눈다. 각 파트는 그 자체로 완결된 한 차시다.

### 2.1 분할 기준 — 분석 절차의 전·후반

**금지**: "1부 이론 / 2부 실습" 식의 분리. 이것은 폐기된 구조다.

**채택**: 분석 절차를 시간 순으로 갈라, 각 파트 안에 **이론과 실습을 함께** 넣는다.

| 파트 | 다루는 절차 | 끝났을 때 학생이 할 수 있는 것 |
|---|---|---|
| **1부 (65분)** | 문제 설정 → 자료 확인 → 방법 선택 → 첫 추정 | 왜 이 방법이 필요한지 설명하고, 코드를 돌려 기본 추정치를 얻는다 |
| **2부 (65분)** | 진단 → 보정·확장 → 결과 해석 → 의사결정 연결 | 추정치를 믿어도 되는지 판정하고, 숫자를 결정 근거로 옮긴다 |

장의 성격에 따라 경계는 조정한다. 기준은 하나다 — **1부가 끝났을 때 학생 손에 결과물 하나가 남아야 한다.**

### 2.2 파트 표기

각 파트 머리에 다음을 둔다.

```markdown
# 1부 (65분). {이 파트에서 하는 일}

> **이 파트가 끝나면**: {완성되는 산출물 한 줄}
> **다루는 절**: {N.1 ~ N.k}
```

## 3. 이론·실습 통합 서술 (필수)

이론 설명과 실습을 별도 절로 떼어 놓지 않는다. **개념 하나를 설명한 자리에서 바로 코드와 출력을 붙인다.**

각 개념 단위를 다음 네 토막으로 쓴다.

1. **왜 필요한가** — 이 계산을 하지 않으면 무엇이 잘못되는지 구체 상황으로 제시
2. **무엇을 계산하는가** — 입력과 출력, 계산 흐름을 말로 서술 (수식은 최소한, 쓰면 각 항을 풀어 설명)
3. **코드로 해 보기** — 핵심 5~15줄 + `_전체 코드는 practice/chapter{NN}/code/{파일명}.py 참고_`
4. **결과를 읽는 법** — 실제 출력값을 싣고, 숫자마다 무슨 뜻인지, 어느 값이 나오면 무엇을 해야 하는지

네 번째가 이 규격의 핵심이다. **출력을 보여 주고 끝내지 않는다. 반드시 판정 기준을 함께 준다.**

예: "F통계량 3.2가 나왔다 → 10 미만이므로 약한 도구변수다 → 이 추정치는 보고하지 않고 도구변수를 다시 찾는다"

## 4. 비유 사용 (허용, 조건부)

학부생 대상이므로 비유를 적극 쓴다. 단 다음 세 조건을 지킨다.

1. **속성 대응을 명시한다** — 무엇이 무엇에 해당하는지 한 줄씩 짝지어 적는다
2. **비유 뒤에 정확한 서술을 붙인다** — 비유가 설명을 대신하지 않는다
3. **분위기가 아니라 구조(순서·조건·인과)를 옮긴다**

비유가 깨지는 지점도 함께 적는다. "이 비유는 여기까지만 맞다"를 한 줄 넣는다.

**쓰지 않는 것**: 의인화("모델이 확신한다"), 감정어("무섭다", "아프다"), 평가어("완벽하다", "훌륭한"), 과장.

## 5. 문체

- **종결어미**: "~한다 / ~이다" 격식체 평서문으로 통일한다. (이 프로젝트는 geoai lecture 트랙의 "~함/~임"과 다르다 — 기존 `lecture/chapter01.md`·`chapter06.md`의 문체를 따른다.)
- **문장**: 짧고 명확하게. 한 문장에 한 개념.
- **단문 연속 금지**: 서술형 문단에서 단문(절이 하나뿐인 문장)을 3개 이상 연속하지 않는다. 인과·조건·대조가 있는 인접 문장은 접속어미(-어서/-므로/-지만/-면서)로 묶는다. 절차 나열·체크리스트는 예외.
- **개조식 허용**: 불릿과 번호 목록을 자유롭게 쓰되, 각 항목에 충분한 설명을 붙인다. 나열만 하지 않는다.
- **중첩 불릿 금지**: 불릿은 한 단계만 쓴다.
- **이모지 금지**: 절 제목의 🌟🎭📊 같은 장식 이모지를 쓰지 않는다. (기존 ch02~05에 남아 있으면 제거한다.)
- **용어**: 전문 용어는 첫 등장 시 **굵게** + 영문 병기. 이후에는 그대로 쓰되 한 절 안에서 무엇을 가리키는지 다시 연결한다.

## 6. 장 구성 골격

```
# {N}장. {제목}

## 이 장 한 줄 요약
## 학습 목표            — 6~8개, "무엇을 할 수 있게 되는가"로 서술
## 이 장을 읽는 방법     — 두 파트 구성 안내, 실습 코드 위치

# 1부 (65분). {하는 일}
> 이 파트가 끝나면 / 다루는 절

## {N}.1 ~ {N}.k        — 각 절이 개념 하나. §3의 네 토막 구조로 서술
## 1부 정리             — 지금까지 만든 것, 다음 파트로 넘길 것

# 2부 (65분). {하는 일}
> 이 파트가 끝나면 / 다루는 절

## {N}.k+1 ~ {N}.m      — 진단·해석·결정
## 결과를 어떻게 읽는가   — 산출물 해석 종합
## 실무 적용 점검표      — 새 과제에 적용할 때 확인할 항목

## 핵심 정리
## 연습 문제            — 3~5개, 계산이 아니라 판단을 묻는다
## 참고문헌
```

절 번호는 `docs/chapter{NN}.md`와 맞춘다.

## 9. 작성 후 자기 점검

1. 65분 두 파트로 나뉘어 있고, 각 파트 머리에 산출물 안내가 있는가
2. "1부 이론 / 2부 실습" 식 분리가 남아 있지 않은가
3. 각 개념마다 코드와 출력 해석이 붙어 있는가 (§3의 네 토막)
4. 출력 해석에 **판정 기준**이 있는가 ("이 값이면 무엇을 한다")
5. 이모지·의인화·감정어·평가어가 없는가
6. 종결어미가 "~한다/~이다"로 일관되는가
7. 서술형 문단에 단문이 3개 이상 연속하지 않는가
8. 중첩 불릿이 없는가
9. 인용한 수치가 기존 본문에서 온 것인가 (지어낸 숫자 0건)
10. 절 번호가 `docs/chapter{NN}.md`와 맞는가
