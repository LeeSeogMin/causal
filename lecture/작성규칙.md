# 강의노트 작성규칙

6장(`chapter06.md`)에서 확정한 규칙이다. **7~12장에 그대로 적용한다.**
새 장을 쓰기 전에 이 문서를 먼저 읽는다.

- 대상: 대학 2~3학년 학부생
- 산출물: `lecture/chapterNN.md` → `pdf/chapterNN.pdf`
- 기준 사례: `lecture/chapter06.md`

## 1. 구성

### 1.1 전체 골격

| 순서 | 항목 | 분량 기준 |
|------|------|-----------|
| 1 | 제목 + 학습 목표 (6~7개) | 10줄 |
| 2 | 이 장 한 줄 요약 | 2줄 |
| 3 | 이 장을 읽는 방법 | 5줄 |
| 4 | **1부. 이론과 방법** | 350~450줄 |
| 5 | **2부. 실습** | 500~700줄 |
| 6 | 실습 정리: 자주 나는 오류 (표) | 15줄 |
| 7 | 과제 3개 | 20줄 |
| 8 | 핵심 정리 (코드블록) | 35줄 |
| 9 | 더 공부할 자료 (접속 확인한 URL) | 25줄 |
| 10 | 참고문헌 | 20줄 |

**최소 400줄, 1부와 2부를 반드시 나눈다.**

### 1.2 절 번호

`docs/chapterNN.md`의 절 번호를 유지한다. 6장은 6.1~6.9였다.

### 1.3 실습 구성

- **실습은 최소 2개, 권장 4~5개.**
- 실습 번호와 파일 번호를 함께 적는다: `## 실습 2 (6-8). 전용 패키지로 2SLS 돌리기`
- 실습 순서는 파일 번호 순이 아니라 **배우는 순서**로 정한다.
- 각 실습의 고정 구성: **목적 → 실행 → 실제 출력 → 출력 해석 → 그래프 읽기 → 확인 문제**

## 2. 다루는 범위

### 2.1 넣는 것

- 실습 코드가 있는 방법만 다룬다. **코드가 없는 방법은 이름도 꺼내지 않는다.**
- 실습에서 바로 적용할 수 있는 절차와 판정 기준.
- 결과를 보고서에 옮길 때 필요한 형식(표 항목, 붙일 주석 문장).

### 2.2 빼는 것

- **방법론 비교표·성능 순위표.** 여러 모델을 나열해 우열을 가리는 절을 만들지 않는다.
- **방법의 발달 과정·계보.** "2017년에 제안되었고 2019년에 개선되어…" 같은 서술.
- 실습에 쓰지 않는 검정·지표(6장에서는 과식별 검정을 뺐다).
- 학부 수준에서 이해하지 않아도 실습에 지장 없는 유도·증명.
- 일부러 실패 사례를 만들어 보는 실습(6장에서 약한 도구변수 재현 실습을 뺐다). **"쓰지 마라"는 규칙 한 줄로 충분하다.**

### 2.3 판단 기준

새 내용을 넣을지 망설여지면 이렇게 묻는다.

> **이것을 몰라도 실습을 돌리고 결과를 해석할 수 있는가?**

그렇다면 뺀다.

## 3. 수식과 개념 설명

- **1부 전체에서 수식 3~5개.** 그 이상은 넣지 않는다.
- 수식마다 **실제 데이터의 숫자를 대입해** 한 번 계산해 보인다.
- 기호를 쓸 때는 그 자리에서 무엇을 가리키는지 밝힌다.
- 개념 도입 순서를 지킨다: **일상 사례 → 같은 구조의 정책·비즈니스 사례 → 방법 이름**

6장 예시:

```
헬스장 등록과 체중 (일상)
  → 직업훈련과 취업률, 대학 졸업과 임금 (정책)
  → 내생성(endogeneity)
```

## 4. 문장 규칙

### 4.1 본문 서술은 사실 그대로

제목과 본문에 수사를 쓰지 않는다. 무엇이 일어나는지 그대로 적는다.

| 쓰지 않음 | 쓴다 |
|-----------|------|
| OLS가 조용히 틀리는 상황 | OLS 추정치가 어긋나는 조건 |
| 바깥에서 온 흔들림만 쓰기 | 처치의 일부만 골라 쓰는 방법 |
| 전통 IV가 막히는 세 지점 | 2SLS가 잘 맞지 않는 세 경우 |
| 직선 자로 굽은 길 재기 | D와 Y의 관계가 곡선일 때 |
| 2SLS로 편향을 걷어내기 | OLS와 2SLS의 추정값 차이 확인 |

### 4.2 은유는 금지, 비유는 대응표와 함께

| 구분 | 정의 | 처리 |
|------|------|------|
| **은유** | 대응 관계를 밝히지 않고 A를 B로 바꿔 부름. 의인화 포함 | 쓰지 않는다 |
| **비유** | A가 B와 같은 구조임을 밝히고 **무엇이 무엇에 대응하는지 표로 명시** | 쓴다 |

**비유를 쓰는 형식은 고정한다.**

```markdown
**비유: 정수기 필터**

| 정수기 | 2SLS |
|--------|------|
| 수돗물 원수 | 원래 처치변수 D |
| 물에 섞인 불순물 | D 안에서 U와 상관된 변동 |
| 필터 | 1단계 회귀 `D ~ Z + X` |
```

세 가지를 지킨다.

- `**비유: ...**` 라벨을 붙여 본문 서술과 구획한다.
- 대응표를 반드시 붙인다. 대응표 없는 비유는 은유다.
- 대응이 깨지는 지점이 있으면 표 아래에 적는다.

**장당 비유 3~5개.** 그 이상은 본문이 수사로 덮인다.

### 4.3 일상 사례

비유와 다르다. 비유는 다른 영역의 구조를 빌려 오지만, **사례는 같은 현상의 실제 사건**이다. 제한 없이 쓴다.

6장에서 쓴 사례: 헬스장 등록과 체중, 학원 수강과 성적, 배달앱 쿠폰과 주문액, 맛집 가격과 대기줄, 편의점 매출 변수, 국비 코딩 교육.

### 4.4 한국어 문장

| 유형 | 쓰지 않음 | 쓴다 |
|------|-----------|------|
| 무생물 주어 | 이 방법은 정확도 향상을 제공한다 | 이 방법을 쓰면 정확도가 올라간다 |
| 피동 남용 | ~되어진다 / ~로 여겨진다 | ~한다 / ~로 본다 |
| 「가지다」 | 높은 신뢰도를 가진다 | 신뢰도가 높다 |
| ~에 대한·에 있어서 | 성능에 있어서의 개선 | 성능이 좋아진 정도 |
| 대동사 | 분석을 수행한다 | 분석한다 |
| ~중 하나 | 핵심 요인 중 하나이다 | 핵심 요인이다 |
| 「들」 남용 | 결과들은 지표들을 | 결과는 지표를 |
| 영어 직역 | 이것이 ~인 이유다 | ~ 때문이다 / 까닭이 여기 있다 |
| 콜론 연결 | 이 문장이 붙어야 한다: "..." | 이 문장을 넣는다.<br>(줄 바꿔 인용블록) |

추가로,

- 한 문장에 한 가지만. 60자를 넘으면 끊는다.
- 정도를 형용사로 말하지 않는다. "크게 개선"이 아니라 "0.71 → 0.78".
- 결론 문장에는 **누가·무엇을 한다**가 들어간다.
- 감정어·자평을 쓰지 않는다. "깔끔하게 정리했다", "훌륭한 결과" 금지.

### 4.5 목록

- **중첩 불릿을 쓰지 않는다.** 한 단계만 쓴다.
- 항목이 3개를 넘고 각 항목에 속성이 둘 이상이면 표로 바꾼다.

## 5. 그림과 표

### 5.1 개념도

- `diagrams/make_chapterNN.py`에 matplotlib 코드로 작성하고 `diagrams/NN-n.png`로 저장한다.
- 강의노트에서 `![그림 NN-n. 제목](../diagrams/NN-n.png)`로 참조한다.
- **mermaid를 쓰지 않는다.** PDF 변환에서 렌더링되지 않는다.
- 생성 후 반드시 이미지를 열어 **레이블이 겹치는지 확인**한다.

### 5.2 실습 결과 그래프

- 실습 스크립트가 만드는 PNG를 그대로 참조한다: `![...](../practice/chapterNN/code/....png)`
- **"그래프 읽기" 절을 반드시 붙인다.** 패널 (a)(b)(c)마다 무엇을 보라는 것인지 한 줄씩 적는다.
- 그림에 없는 내용을 설명하지 않는다. 그림을 실제로 열어 보고 쓴다.

### 5.3 표

- 표에는 항상 판정 열이나 해석 열을 넣는다. 숫자만 나열하지 않는다.
- 결과 비교표에는 "신뢰구간이 참값을 포함하는가" 같은 판정 열을 둔다.

## 6. 실습 작성

### 6.1 숫자는 반드시 실행해서 얻는다

- **강의노트에 싣는 모든 출력은 직접 실행한 결과여야 한다.** 지어내지 않는다.
- 실습 코드를 고쳤으면 다시 돌려 출력을 갱신한다.
- 시드가 고정되어 있어도, 스크립트마다 참값이 다르면 그 사실을 명시하고 **서로 다른 실습의 숫자를 나란히 놓고 비교하지 않는다.**

### 6.2 출력 해석 방식

출력의 숫자를 하나씩 인용하고 뜻을 붙인다.

```markdown
**`F-통계량: 295.05`**

기준선 10을 크게 넘는다. 관련성 조건은 충족이다.
```

- 숫자가 어디서 나왔는지 계산 과정을 보인다.
- 그 숫자로 무엇을 판단하는지 적는다.
- 판단이 뒤집히는 조건을 적는다.

### 6.3 코드의 한계를 숨기지 않는다

간소화 구현이면 원래 방법과 무엇이 다른지 표로 밝힌다. 6장 예시:

| 항목 | 원래 DeepIV | 이 실습 코드 |
|------|-------------|--------------|
| 1단계 | D가 나올 범위 전체를 학습 | 평균만 예측 |

### 6.4 실습 코드를 고칠 때

- 증상을 덮지 않고 **근본 원인을 찾아 고친다.**
- 코드 상단 docstring에 `수정 이력`을 남긴다. 무엇이 왜 틀렸고 어떻게 고쳤는지 적는다.
- 고친 뒤 반드시 실행해 결과를 확인하고, 강의노트의 출력도 갱신한다.

## 7. 인용과 자료

- URL을 싣기 전에 접속을 확인한다(HTTP 200). 확인 날짜를 명시한다.
- 실습에서 쓰지 않는 방법의 원 논문은 참고문헌에서 뺀다.
- 수치를 인용할 때 출처를 병기한다. 확인하지 못했으면 "확인 필요"라고 적는다.

## 8. 작업 순서

새 장을 쓸 때 이 순서로 진행한다.

1. `docs/chapterNN.md`를 읽고 절 번호와 다룰 범위를 정한다.
2. `practice/chapterNN/code/`의 실습 코드를 **전부 실행**해 실제 출력을 확보한다.
3. 실행이 실패하거나 결과가 이상하면 근본 원인을 찾아 고친다(§6.4).
4. 실습 코드가 없는 방법은 목록에서 뺀다(§2.1).
5. `diagrams/make_chapterNN.py`로 개념도를 만들고 이미지를 열어 확인한다(§5.1).
6. 1부를 쓴다. 수식은 3~5개, 비유는 3~5개, 전부 대응표를 붙인다.
7. 2부를 쓴다. 실습마다 실제 출력을 붙이고 줄별로 해석한다.
8. 정리·과제·핵심 정리·참고문헌을 쓴다.
9. **점검**(§9)을 돌린다.
10. **PDF로 변환한다**(§10).

## 10. PDF 변환

**각 장을 다 쓰면 반드시 PDF로 변환한다.**

```bash
python md2pdf.py lecture/chapter07.md     # 한 장
python md2pdf.py --all                    # 전부
```

출력은 `pdf/chapterNN.pdf`다.

필요 도구는 `pandoc`과 `typst` 두 가지다. 변환 후 PDF를 열어 아래를 확인한다.

- 한글이 깨지지 않는가 (본문과 코드블록 양쪽)
- 그림이 빠지지 않았는가
- 표가 페이지를 넘어가며 잘리지 않는가
